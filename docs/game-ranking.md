# Game catalog ranking

The default public `/games` list uses Vefa's preferences, rather than IGDB's undocumented homepage formula. Card scores and HowLongToBeat hours are independent of ordering. No user log, private rating, or playtime enters the algorithm.

`OWNER_RANKING_CONFIG` is the versioned source of preferences. Version `owner-taste-v1` blends 65% taste affinity and 35% the existing current-interest score. Affinity adds Action (0.15), RPG (0.25), Open world (0.25), Single player (0.20), and an RPG + Open world + Single player combination (0.15). A verified multiplayer/co-op-only game loses 0.25 affinity. Affinity is clamped to 0–1 before blending. A game does not need every preferred tag to benefit. Missing, empty, or future/unknown mode IDs never imply either single-player or multiplayer-only.

Current interest retains the existing per-signal percentile blend: IGDB Visits 70%, Playing 20%, Steam 24-hour peak 10%, reweighted over signals actually present. This prevents a raw-counter outlier from flattening every other game. Missing interest adds no interest contribution; an unclassified game is ordered by its available interest contribution. HLTB completions, backlog counts and duration do not affect ranking. Duration alone does not establish whether Vefa prefers a game.

The existing `catalog.popularity.refresh` job hydrates relevant game-mode metadata, fetches interest, and writes both scores atomically. The recommendation's version and update time are stored for inspection. Strict CLI runs still synchronize all considered games into search so a retry repairs an earlier failed index write. HLTB supplementation preserves curated hours.

Game-mode hydration uses explicit IGDB IDs in batches of at most 500, at most 20 batches / 30 seconds per refresh, sharing the client's request spacing below 4 requests/second. Action, RPG and Open world candidates are visited in current-interest/UUID keyset order. Successful lookups age out after 90 days, so later runs rotate through remaining candidates. A valid response omitting a game records the attempt age but retains its unknown or previously known modes; it never means an empty mode list. Failed or malformed batches do not change lookup state. Provider unavailability is reported separately and does not prevent interest/ranking refresh; database errors fail the job.

Default browsing reads SQL directly, ordered by recommendation descending, interest descending, title and UUID. The matching index makes pagination deterministic at a fixed catalog revision. Before the first successful recomputation, null recommendations fall back to interest order. Typed searches preserve their existing Typesense title relevance; their SQL fallback still puts exact and prefix title matches ahead of taste. Public DTOs do not expose the internal recommendation, weights or diagnostics. Existing review labels and conditional HLTB hours remain unchanged.

Apply generated migration `0028_needy_wallop.sql` after movie migration `0027_movies_catalog.sql`, then publish the API/worker and enqueue the normal registered popularity job. No additional credential or recurring job type is needed. The existing daily schedule remains responsible for refreshes. Game-mode coverage fills over bounded runs; an initial refresh does not imply that every game has verified modes.
