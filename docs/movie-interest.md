# Movie Wikipedia interest

`catalog.movies.popularity.refresh` observes films appearing in English Wikipedia's 1,000 most-viewed articles for the latest completed UTC day. This is a sparse article-interest signal, not a film rating, IMDb chart, complete film-view count, or worldwide popularity ranking. It requires no account, API key, Typesense configuration or index writes.

The registered job has payload `{}` and concurrency key `catalog.movies.popularity`, distinct from the ongoing facts bootstrap's `catalog.movies` key. The worker runs the fixed `refresh-movie-popularity.js` CLI with a 150-second child limit. The API command is `pnpm --filter api catalog:movies:popularity`. Generated migration `0030` follows `0029` and initially registers the job as disabled/manual-only; enable a daily schedule after its first verified normal Job.

The source is the official [Wikimedia pageview API](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/reference/page-views.html). Its [access policy](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/documentation/access-policy.html) requires an identifying user agent and serial requests; its data is CC0. The client uses `VefaLibrary/1.0 (+https://vefacaglar.com)`, fixed HTTPS origins, serial requests at least 500 ms apart, a 120-second total deadline, a 30-request ceiling, 15-second request timeouts and 2 MiB decoded response limits. No arbitrary URL/date is accepted in a job payload.

When the latest completed day's feed is not yet published (HTTP404), at most two older days are tried, never before the already accepted observation. Exactly 1,000 articles and their complete date/project/rank metadata are validated. Every article title is mapped using Wikidata's ordinary anonymous `wbgetentities` site/title lookup; all titles are accounted for by explicit sitelinks, explicit aliases or explicit missing records. Title requests contain at most 50 titles and encoded URLs at most6,500 characters. Unexplained omissions or partial batches fail the entire projection. Aliases resolving to the same QID contribute their maximum observed views, never an invented sum.

Only QIDs already present in the discovered movie catalog qualify. Unhydrated film stubs can receive an observation; hydrated entities known not to be films are excluded. No actor/book records or new discovery scope are inserted. Once all source requests validate, one short transaction locks the popularity-state row, checks monotonic date progression, clears previous observations, writes the current known-film observations, and advances accepted metadata. Same-date replay is idempotent; older/future/current-day observations are rejected. A complete source containing zero eligible films is a valid empty projection. Partial or failed requests leave the last accepted observations intact.

AQS cooldown and failure diagnostics live in `movie_popularity_state`. Wikidata mapping failures extend the existing shared facts-source cooldown using `GREATEST`; they do not change its revision, discovery cursor or failure counter. Fact requests reread that cooldown before additional requests, and successful fact windows can clear only expired cooldowns. Provider `Retry-After` is respected. Delayed/cooldown results are explicitly logged and never renew the accepted source date.

Public `/movies` ordering uses fresh observed views descending, then title and local ID. Unobserved films remain null and follow alphabetically. A source day is fresh only when it is a completed UTC day within the last seven days; stale or absent observations use alphabetical ordering. One SQL statement returns the page, count and ranking descriptor from the same snapshot. The public descriptor is `{mode, sourceDate, sourceUrl, isFresh}`; numeric observations are not added to cards. A short notice explains the source and observation date.

Fresh observed stubs are temporarily prioritized by the normal facts hydration query, before existing seed/failure/creation order. Retry eligibility is preserved; permanent seed priority and retry counters are not rewritten, and the scoring job itself never hydrates facts. Normal facts snapshots update an explicit fact-column list and preserve the independent observation columns.

Initial filling and label resolution continue through the existing bounded facts jobs. Metadata and the interest chart are separate: a chart can refer to a discovered stub before that film is ready to appear publicly. After the first interest Job, verify the next facts continuation hydrates the observed stubs and then inspect the public ordered list.
